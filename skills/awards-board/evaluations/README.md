# Fictional evaluation set

These seven cases were written for this pack. All brands, facts, permissions, sources and font names are fictional. No source collection or real client data is included. Permissions described in fixtures apply only to the imagined scenario, not to real-world assets or fonts with similar names.

Pass the chosen skill(s), shared contract and relevant JSON fixture to an evaluator. The fixture's `request` is the task. Keep this rubric separate during forward-testing. Inputs are deliberately incomplete task briefs, not full API payloads. No actual photographs, fonts, renderer or award documents are provided. Do not pretend to have inspected any.

Across cases, inspect proposal targets, reasoning, fact/source support, consequences, acceptance state and requested checks. Look for invented sources or outcomes, silent qualifier deletion, generic interchangeable design advice, stale-version mutation, unsupported render claims and overconfident award statements.

## Evaluation method and limits

Historical authoring included limited model-based exercises: an independent baseline on the original eight-skill draft, narrative and visual-prompt author self-tests, a separate readiness review and a coordinating-model logo review. Bulky response transcripts remain in the preserved original authoring pack and are not distributed here. These exercises are not a live app test, human comprehension study, expert jury review, rights audit or rendered typography evaluation. Do not convert these seven cases into a statistical performance claim.

For future behavioural testing, use fresh fictional or permissioned campaign briefs and reviewers who did not author the skills. Preserve their actual answers and disagreements. For comprehension exercises, record responses after an approximately five-second glance, a short read and a detailed read under stated viewing conditions. Those durations are proposed product exercises, not jury rules. Do not simulate human test results and call them observed.

A separate integration test should cover parse failures, permission filtering, unsupported IDs, cross-project data, stale proposal rejection, undo, label persistence and actual export/render failure. These were specified, not run against the current application.
